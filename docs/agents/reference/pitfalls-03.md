- **Zalo error policy/action retry**: `auto_error.zalo_action_codes` rỗng là policy global; mọi lookup raw `zalo_error_codes` phải truyền action phát sinh để cùng mã Zalo không disable nhầm action. Mã `221` phải giữ ở cả policy tìm SĐT (`312,221`, scope `zalo_find_phone_user`) và kết bạn (`221`, scope `zalo_add_friend`), mỗi policy nghỉ 60 phút; không loại `221` khỏi tìm SĐT khi tách scope ([migration khôi phục](../../../migrations/migration_v259_restore_zalo_phone_221_hour_limit.sql:1)). Sau khi helper trả `deliveryCommitted=true`, lỗi/pause/account-stop phía sau không được đưa input về `chờ xử lý`. `stopAfterTarget` từ policy terminal vẫn phải truyền `pendingNote` đã render từ `noti_campaign`; không để `detail_status` làm mất lý do rồi hiển thị fallback kiểm tra tài khoản ([errorPolicyRepository.ts](../../../src/main/data/repositories/errorPolicyRepository.ts), [campaignScheduler.ts](../../../src/main/services/campaignScheduler.ts)).
- **Zalo join group by link**: input data stores the group link in `auto_campaign_input_data.uid`; accept and normalize `zalo.me/g/...` and `zaloapp.com/qr/g/...` to `https://zalo.me/g/...` in upload/runtime. `joinGroupLink` code 178 creates detail status `đã tham gia` with `counts_toward_limit=false` and no `error_code`; code 240 is `thành công`, counts quota, and mirrors group contact with `is_joined=false`.
- **Zalo group theo thời gian thực**: listener lifecycle stays in `ZaloRuntimeService`; [zaloRealtimeGroupCampaignManager.ts](../../../src/main/services/zaloRealtimeGroupCampaignManager.ts) only routes `group_event`/`message`/`reaction` into campaign data. Received/duplicate data logs go to `auto_campaigns.log` ("Lịch sử chạy"), not `auto_campaign_details` ("Kết quả chạy") and not the progress panel.
- **Zalo auxiliary skip conditions**: `Kiêm gắn tag Zalo` hỗ trợ bỏ qua bạn bè hoặc một trong nhiều tag được chọn; `Kiêm đổi tên` bỏ qua bạn bè độc lập. Ưu tiên `isFr`/`is_fr` từ API; thao tác bật điều kiện mà thiếu trạng thái thì gọi `getFriendRequestStatus` và đọc `is_friend`, tối đa một lần/tài khoản/UID trong mỗi lượt xử lý input, dùng chung cho tag/alias kể cả kết quả lỗi/thiếu. Sau kiểm tra vẫn chưa xác định thì cảnh báo và tiếp tục; lifecycle stop/recovery luôn chặn mutation. Không tin cờ `target.isFriend` mặc định hoặc cache sang input sau. Kiểm tra tag trong chính snapshot `getLabels()` sẵn có, skip chỉ ghi tiến trình. `zaloTagSettingsByAccountId` giữ tag cần gắn/loại trừ riêng theo tài khoản chính/phụ; bulk-save chỉ giữ map của từng campaign, runtime resolve bằng tài khoản thực hiện và không fallback sang tài khoản khác khi có map. Thiếu cấu hình điều kiện bỏ qua không chặn gắn tag/đổi tên: cờ thiếu coi như tắt; bật loại trừ tag nhưng danh sách thiếu/rỗng/không hợp lệ thì cảnh báo và vẫn gắn tag của tài khoản đang chạy. Thiếu chính tag cần gắn là lỗi thiếu đích riêng, không được mượn tag tài khoản khác. Chỉ campaign thiếu map hoàn toàn dùng trường phẳng legacy. Giữ contract cùng Chat runtime; xem [hướng dẫn và smoke](../../../docs/ZALO_AUXILIARY_SKIP_CONDITIONS.md).
- **Zalo campaign user upsert**: user-target Zalo campaigns may upsert `zalo_users` + `auto_account_contacts.person`, but only from metadata actually returned by Zalo API (`findUserByPhone`, `getAllFriendsPage`, `getUserProfile`). Do not populate contact metadata from `auto_campaign_input_data`; do not set `is_friend=false` unless API returns an explicit `isFr`/friend status. `zalo_message_group` does not upsert groups or fetch extra group metadata.
- **Zalo share message mode**: friend/group campaign option `extraSettings.zaloMessageSendMode='share'` bypasses workflow execution after scheduler preflight and sends text via raw Zalo `/api/message/mforward` or `/api/group/mforward` in batches up to 50. Do not use `zca-js api.forwardMessage` for campaign share mode because it reuses one `clientId` for the whole batch; build per-target `clientId` values and map success/fail by `clientId` (or target id when Zalo returns one). Skip own UID before sending friend share batches so one self target does not make Zalo reject the entire batch with `114`. Khi batch có ít nhất một target thành công, mọi target lỗi/invalid/thiếu result chỉ ghi detail terminal, không tự retry, không áp side effect/bad-target policy và không dừng campaign. Chỉ batch `0` thành công mới áp policy có side effect mạnh nhất đúng một lần và đếm từng failure đủ điều kiện theo threshold `err_undefined`; nếu không policy/threshold nào dừng thì vẫn phải fail-safe pause campaign. Mọi nhánh dừng sau batch phải settle unit rồi đưa campaign khỏi `đang chạy` trước khi release account; manual pause của user luôn thắng transition hậu batch.
- **Zalo friend "Danh sách không gửi tin"**: `zalo_message_friend` can enable `extraSettings.zaloFriendBlocklistEnabled` with a contact group `purpose='zalo_friend_blocklist'` scoped to the same account. Scheduler loads UID snapshot once, checks before quota/workflow/API/share batch, marks skipped input data `hoàn thành` with note/date, does not create `auto_campaign_details`, and does not count quota. Normal mode logs each skipped target in progress; share mode logs only the total skipped count.
- **Zalo remarketing customer picker**: `zalo_message_remarketing_customer` selects targets from previous Zalo message `auto_campaign_details`, but detail JSON is only history/fallback. Resolve display data from `auto_campaign_input_data`, `zalo_users`, `auto_account_contacts`, `zalo_group_members`, and `zalo_groups`; friend status must come from `auto_account_contacts.is_friend` or `zalo_users.is_fr`, not `data.target.isFriend`.
- **Zalo auto-materialized input data**: `zalo_message_friend` modes `all_friends`/`tagged_friends` materialize friend rows only once per campaign and clone must not copy those rows or materialized markers. `zalo_message_friend_recommendation` calls `getFriendRecommendations()` once per campaign/account at runtime, materializes UID/name/phone only into `auto_campaign_input_data`, marks empty results as completed, and upserts contacts only later when resolving each UID. `zalo_message_birthday` materializes by run date from `getAllFriendsPage(...).sdob.slice(0, 5) === dd/mm`; daily is one-shot, while weekly/monthly soft-delete old birthday input rows and clear birthday materialized metadata before the next occurrence.
- **Zalo campaign read pacing**: live reads used to materialize friend, birthday, recommendation, sent-request and tag-filter campaign inputs must wait randomly 2–5 seconds before the first request and between pages/reads. HTTP 429 retries after 15/30/60 seconds while honoring pause, runtime stop and Server hard-stop boundaries; exhausting 429 must propagate as an error and must not mark recommendation/cancel-request materialization complete.
- **Zalo contact scan is API-only**: friend/group/group-member data scans must go through `ZaloRuntimeService`; do not create webviews/browser profiles and do not call extra link APIs during group scan. `ContactLoader` friend scan delays randomly 2–5 seconds after `checkSession()` and between 500-row `getAllFriends` pages; HTTP 429 from session/page calls is transient and retries after 15/30/60 seconds while still honoring scan cancellation. Friend/group scans may call `getLabels()` once to sync Zalo label catalog (`contact_type='zalo_tag'`) and mirror tag membership from `label.conversations` into `auto_account_contacts.extra_data.zaloTagIds`/`zaloTagNames`/`zaloTags`; do not backfill Zalo tags from old `auto_campaign_details`. `DataScanModal` should keep Facebook table columns stable; Zalo-only avatar/phone/tag columns are gated by platform, while Zalo group `Link` displays the stored nullable `auto_account_contacts.url`. DataScan Zalo tag/akaBiz tag filters are query state sent through shared list query types and main repositories (not renderer-only UI filters); keep multi-select OR within each tag filter, AND between Zalo tag and akaBiz tag filters, and preserve the `Chưa gắn tag` flags. Group-member link mode may decode QR payloads like `zaloapp.com/qr/g/...` but must normalize them to `https://zalo.me/g/...` before calling runtime.
- **App Server scan datasets**: Server không Chat dùng `ContactLoader.contactDatasetAuth=server_claim` và tokenized account claim để chốt bộ dữ liệu qua RPC v277; không đọc mật khẩu Desktop hoặc bỏ lỗi finalize. Desktop Chat vẫn giữ credential RPC; release phải dùng đúng token, và partial/failed giữ semantics snapshot hiện có. Xem [ZALO_SERVER_CONTACT_DATASET.md](../../../docs/ZALO_SERVER_CONTACT_DATASET.md).
- **Zalo group-member picker roles**: `zalo_message_group_member` must request role sorting before dataset pagination so owner is first, then admins, then members; sorting only the current renderer page is incorrect. Its campaign-only leadership exclusion must recognize `zaloGroupRole` plus `isCreator`/`isAdmin` fallbacks and re-filter selected output after bulk/range selection.
- **Chat Sync scan retry**: Chat runtime now owns read-query HTTP 429 retries (15/30/60 seconds) and streams wait progress through [zaloChatApiClient.ts](../../../src/main/services/zaloChatApiClient.ts). `ContactLoader` forwards progress with the active run key and must not retry `data_scan_rate_limit_exhausted`; keep its existing page pacing and local/non-Chat retry behavior. Server exhaustion messages omit raw `429` so older desktop versions do not multiply the retry budget.
- **DataScan pagination/selection**: non-Page-Inbox data tables use backend pagination/search/export through account contact, Zalo group member, or Zalo remarketing list APIs; default page size is 100. Header checkbox selects all matching backend filters across pages, tracks exclusions, and export/add-to-campaign/create-group must fetch the backend selection instead of only current page rows. Page Inbox keeps its existing local SQLite pagination path.
- **Giới tính bạn bè Zalo**: list/export contact đọc `zalo_users.gender` qua FK trong cùng HTTP query, mapper đưa vào `extraData.gender`; bảng `zalo_friends` và Excel hiển thị `0` → Nam, `1` → Nữ, thiếu/khác → Chưa xác định. Không ép `null`/chuỗi rỗng thành `0`; giữ left join để không mất contact thiếu hồ sơ. Smoke: `node scripts/run-account-contact-status-filter-smoke-test.cjs`.
- **DataScan status before fetch**: nhánh tìm kiếm/tag/selection trong [accountContactRepository.ts](../../../src/main/data/repositories/accountContactRepository.ts:1512) vẫn phải lọc `is_friend`/`is_joined` tại DB khi biết contact type, cho mọi chunk kể cả fetch theo ID; giữ `NULL` trong trạng thái inactive và giữ semantics của bộ lọc JS. Verify bằng `node scripts/run-account-contact-status-filter-smoke-test.cjs`.
- **Page Inbox account switching**: trạng thái danh sách Page đã tải cho account phải là React state và tham gia dependency của truy vấn SQLite trong `DataScanModal`; chỉ đổi `ref` sẽ không tải lại khách hàng khi hai account cùng chọn một Page. Bỏ phản hồi Page/SQLite cũ sau khi đổi account.
- **Page Inbox chọn nhiều khách**: đếm byte từng chunk stdout, chỉ ghép phản hồi một lần; chọn vào chiến dịch dùng projection SQLite `campaign`, lọc/sắp xếp vẫn xét JSON đầy đủ. Xuất Excel/lưu nhóm giữ dữ liệu đầy đủ, không bỏ giới hạn 16/32 MiB; xem [kiểm chứng 5.000–10.000 khách](../../../docs/DATA_COLUMN_FILTERS.md#chọn-500010000-khách-page-inbox--26102026).
- **Async renderer mutation locks**: nút Lưu/Thêm/Xác nhận phải bật trạng thái busy trước `await` đầu tiên và disable trigger trong suốt mutation. Nếu handler có pre-work async hoặc mutation không idempotent, dùng thêm `useRef` mutex đồng bộ để nhiều click trước lần render kế tiếp vẫn chỉ tạo một request; modal không được đóng/chuyển action trong lúc request đang chạy.
- **Heavy-data RPC timeout**: UI/RPC ingest tối đa 10.000 rows; `aka_agent_save_upload_contact_datasets` có function-local `statement_timeout=120s`, còn toàn bộ current/legacy client/service overload của `aka_agent_ingest_data_group` phải giữ function-local `statement_timeout=60s`. Các Data API entrypoint bulk/paging/materialization được liệt kê fail-closed trong [20260904051350_set_heavy_rpc_timeouts_60s.sql](../../../supabase/migrations/20260904051350_set_heavy_rpc_timeouts_60s.sql) cũng phải giữ function-local `statement_timeout=60s` sau mọi `CREATE OR REPLACE FUNCTION`. Không tăng timeout global cho role `anon`/`authenticated`; các RPC scheduler/claim/control polling vẫn giữ timeout ngắn để fail-fast.
- **Bulk RPC/Edge Function timeout**: mọi RPC mới/sửa có thể scan, aggregate, ingest, materialize, export, phân trang hoặc mutate nhiều row qua Supabase Data API phải đặt đúng function-local `SET statement_timeout TO '60s'`; tuyệt đối không để workload bulk rơi về timeout mặc định `anon=3s`/`authenticated=8s` và không đặt `statement_timeout=3s`. Thay đổi phải đi qua `safe-supabase-rpc-migration`, bám exact live signature/checksum, và mọi `CREATE OR REPLACE FUNCTION` sau này phải bảo toàn cấu hình 60 giây. Nếu entrypoint là Supabase Edge Function, phần DB bulk phải gọi một RPC chuyên dụng đã đặt 60 giây; mọi timeout/abort tường minh ở handler hoặc caller cũng phải cho phép đủ 60 giây. Workload không thể hoàn tất an toàn trong 60 giây phải chia batch hoặc đưa vào queue/background worker, không tăng timeout global hay kéo một request đồng bộ lâu hơn. RPC chạy định kỳ mà xử lý bulk phải có single-flight/lock để không chồng lượt; ngoại lệ fail-fast chỉ dành cho poll/claim/control nhẹ, không xử lý nhiều data.
- **Zalo session single-use/race**: one Zalo session should not be logged in concurrently by multiple API instances for the same `auto_account`. `ZaloRuntimeService` serializes login through `apiLoginInflight` and serializes verify/retry through `verifyInflight`; keep new Zalo tasks behind `ensureApi(accountId)` and avoid direct `zalo.login(session)` calls.
- **Zalo credential exposure**: `auto_accounts.zalo_session` is secret runtime credential. Account list mappers/preload/UI must not return raw cookies/session to renderer; only main process Zalo runtime/repository methods may read/write it.
- **Minimized data scans**: `ContactLoader` cũng chạy bằng hidden/offscreen `BackgroundPageManager` + workflow v2 built-in. Không đưa logic scrape mới về visible webview; nếu cần đổi selector/logic quét thì seed/update `auto_blocks`/`auto_workflows` bằng migration.
- **Post-scoped contact filters**: khi thêm nguồn quét theo post, luôn lưu và merge `extra_data.sourcePostRefs` theo cặp `{ source, url }`, đồng thời truyền `AccountContactListQuery.source` trong UI list/export/select. Không quay lại filter bằng cross-product `sources[]` + `sourcePostUrls[]` riêng lẻ.
- **Group-scoped contact filters**: group member scans phải truyền `AccountContactListQuery.source='facebook_group_members'` + `sourceGroupUrl`; không hiển thị/export toàn bộ `person` khi chưa nhập link group hợp lệ.
- **FB media upload**: `page.dropFile()` must avoid viewport coordinates in hidden/offscreen pages and dispatch one bubbling drag sequence to exactly one editor target: use the resolved target when it is a textarea/textbox/contenteditable, otherwise resolve one editable descendant; never fan out the same `DataTransfer` across child and ancestor targets because bubbling duplicates the drop. `fileCount` only means files were injected, not that FB rendered an attachment preview ([pageController.ts](../../../src/main/v2/runtime/pageController.ts)). Comment workflows support exactly 1 image/video per comment: `commentImageOption='all'` chỉ hợp lệ với tối đa một media, còn `random` giữ một pool và scheduler resolve đúng một media cho từng lượt; `fb_comment_at_position` drops into the dialog textbox after clicking the indexed comment box. Sau `dropFile()` trả về, cả `fb_comment_at_position` và `fb_comment_current_post` phải giữ settle delay 10.000ms trước submit; đây là fixed safety delay, không phải tín hiệu DOM xác nhận upload xong ([migration_v234](../../../migrations/migration_v234_facebook_comment_media_settle_delay.sql)).
- **Post media upload**: block 29/2672 dùng `uploadFile` qua form được đánh dấu riêng khi có đúng một input ảnh/video hợp lệ; v304 chỉ fallback `dropFile` trên đúng form đó khi có 0 input, không fallback cho lỗi upload/thiếu file/form hoặc input mơ hồ. Không ghi log kỹ thuật chuyển cách upload vào tiến trình; workflow thật/test dùng block chung, rủi ro global drop handler của Facebook vẫn còn ở fallback ([audit và smoke](../../../docs/FACEBOOK_POST_MEDIA_TEST_OVERRIDES.md)).
