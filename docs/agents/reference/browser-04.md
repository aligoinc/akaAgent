Zalo giữ chung `flatform_type='zalo'` và có đúng ba subtype theo từng account: QR local (`is_zalo_show_web=false,is_zalo_server=false`), Web local (`true,false`), Server zca-js (`false,true`); non-Zalo bắt buộc cả hai cờ false. Mọi login/check/logout, campaign, scan và account action phải định tuyến theo `account.isZaloShowWeb`/`account.isZaloServer`, không dùng `AuthUser.isZaloShowWeb`/`AuthUser.isZaloServer`. QR local ↔ Server giữ `zalo_session`/identity và chỉ đổi khi account idle; mọi chuyển đổi đi qua Web phải xoá session/profile cũ. [zaloWebRuntimeService.ts](../../../src/main/services/zaloWebRuntimeService.ts) chỉ quan sát bootstrap/cookie của đúng webview rồi dựng API bằng `session.fetch`; cookie/bootstrap chỉ nằm local Chromium, DB chỉ lưu identity và trạng thái công khai. Poller đọc `zpsid`/`zpw_sek` mỗi 30 giây và API verify 30 phút làm fallback. Web không gọi `Zalo.login`/`loginQR` và không chạy realtime; QR/Server vẫn browserless.
Zalo Web thiếu bootstrap/lỗi mạng giữ trạng thái đăng nhập gần nhất và chặn lượt chiến dịch mới đến khi API được xác minh; chỉ mất cookie trên trang ổn định mới hạ đăng nhập. Poller 30 giây hiện có tiêu thụ một lượt phục hồi trong RAM trước claim (kể cả account đang `chưa đăng nhập`), chỉ khi account rảnh/còn cookie; bật CDP rồi reload tối đa một lần, không reset lượt bởi dom-ready/re-arm, không reload guest đã crash. Một lượt phục hồi nền tại một thời điểm, claim/cleanup không giữ vòng poller chung; lifecycle vẫn theo dõi và chặn producer/cleanup cũ theo thế hệ. API mới dùng một lần xác minh profile trong build; API cache xác minh mới và chỉ trả lượt phục hồi sau toàn bộ kiểm tra thành công. Hết lượt chờ kiểm tra thủ công/bootstrap mới hoặc mở lại app; log phục hồi qua IPC hiện có, không thêm polling DB/pool. Xem [hướng dẫn](../../../docs/ZALO_WEB_SESSION_RECOVERY.md); smoke: `node scripts/zalo-web-session-recovery-smoke-test.cjs`.
Session QR local lưu trong `auto_accounts.zalo_session` chỉ được tự xoá sau khi cả lần verify hiện tại và lần đăng nhập lại mới đều thất bại bằng lỗi xác thực chắc chắn; update phải CAS theo `zalo_session_updated_at` để không xoá session vừa được thay thế. Lỗi mạng/Zalo tạm thời chỉ đánh dấu chưa đăng nhập và giữ credentials để lần sau thử lại. Luồng Server dùng chung `ZaloRuntimeService` nhưng tuyệt đối không tự xoá session theo nhánh local này.

Tenant Chat giữ nguyên socket App Server cho command/operation hiện hữu và mở thêm socket Chat API chỉ để nhận tiến trình campaign Server. Desktop dùng `ZaloChatApiClient` trong main process; WebApp nhận `campaignWebSocketUrl` + ticket Ed25519 riêng từ akaBizApi. Socket Chat phải chuyển tiếp `campaign:log`, `campaign:status-updated` và `account:status-updated`; trạng thái campaign/account được phát độc lập với log, còn reconnect/hello phải refresh snapshot DB vì state event chỉ live-only. Hai socket có sequence/start boundary và health state độc lập, không được dùng trạng thái socket tiến trình Chat để thay đổi login/logout, operation hoặc trạng thái kết nối App Server.
