Campaign automation chạy qua [src/main/v2/runtime/backgroundPageManager.ts](../../../src/main/v2/runtime/backgroundPageManager.ts) hidden/offscreen `BrowserWindow` theo từng account để minimized vẫn render ổn định. Renderer không tự chuyển page/focus; BrowserPage chọn sẵn account bằng `campaign:browser-select` và hiển thị preview stream bằng `campaign:browser-preview` để user tự vào quan sát. Test/editor vẫn dùng `PageControllerRegistry` của webview visible.

Nội dung có định dạng dùng `extra_settings.formattedContentEnabled=true` cho `facebook_group_post` và các campaign Zalo nhắn tin phone/friend/birthday/group-member/group-realtime/remarketing/friend-recommendation/group; thiếu flag luôn là plain. HTML rich-text được sanitize bằng `htmlparser2`, chỉ giữ cấu trúc từ toolbar TipTap, link `http(s)`, `text-align` hợp lệ và `data-indent` nguyên từ 1..8 trên paragraph/heading; `margin-left` luôn được dựng lại từ cấp indent, không tin CSS đầu vào. Toolbar thụt vào/thụt ra dùng `data-indent` nhiều cấp cho paragraph/heading và sink/lift cho list, tách biệt với blockquote; paragraph/heading dưới `listItem` luôn bị normalize về indent 0 để list chỉ dùng nesting cấu trúc. Simple rich vẫn lưu thành một document nhưng runtime tách dấu `|` nhìn thấy trong text thành các biến thể luân phiên; `\|` là dấu pipe literal, pipe trong `href`, token hoặc spintax không bị tách, và Advanced item luôn là một biến thể nguyên khối. Workflow chưa chuyển V351 của `facebook_timeline_post` không có input data dùng `extra_settings.contentRotationIndex` để xoay nội dung và media cùng chỉ số giữa các lượt chạy; chỉ tăng con trỏ sau khi workflow hoàn thành và reset về `0` khi clone campaign. Spintax/cá nhân hóa chỉ biến đổi text node và phải escape dữ liệu chèn vào HTML. Rich content tắt whole-content AI rewrite; Facebook background không tương thích, UI phải xác nhận rồi chuyển về plain trước khi bật lại. Kho mẫu lưu HTML đã sanitize ở `base_content_html`/`channels`, còn `content` luôn là plain projection để app cũ dùng an toàn.

Chuẩn bị nội dung chung dùng `src/shared/campaignContentPreparation.ts` và adapter `campaignScheduler.ts`; Chat giữ bản shared tương ứng trong runtime-protocol, smoke kiểm tra parity. Hai migration thêm `content_rotation_indexes` theo action trên campaign/input data và chuyển workflow chuẩn/test bằng optional helper + `campaignContentPreparationVersion=1`. Dùng PK input data, tiêu thụ lúc lấy mẫu, một mẫu bỏ RPC; lỗi allocation không fallback/retry. Clone để mặc định `{}`, form/reset không ghi cursor, Zalo share dùng một mẫu/batch. AI bình luận dùng riêng `rewriteCommentContentEachRun`, độc lập `rewriteContentEachRun` của bài đăng. App cũ/workflow chưa chuyển giữ scalar `contentRotationIndex` Profile/Page và tăng sau publish. Không thêm pool/connection. Xem [quy tắc, audit và rollout](../../../docs/CAMPAIGN_CONTENT_PREPARATION.md).

Form campaign Facebook có hỗ trợ nguồn nội dung phải đặt `Copy nguồn nội dung` thành tab thứ tư cạnh `Cơ bản`/`Nâng cao`/`Nhóm mẫu nội dung`; bốn chế độ loại trừ nhau. Khi lưu ở tab nguồn, chỉ lưu cấu hình copy/chia sẻ nguồn và xoá nội dung/media/advanced khỏi payload của campaign mới; runtime vẫn giữ khả năng đọc dữ liệu kết hợp cũ để các campaign đã tạo tiếp tục chạy đúng. Cá nhân hoá trong modal nội dung nâng cao phải dùng đúng item đang thao tác cho cả plain textarea lẫn rich editor, và popover ở hàng action phải mở vào trong biên modal.

Facebook Group rich post tách `sourceContentPlain` khỏi `manualContentNative`, compose source thành HTML an toàn rồi nối manual HTML. Vì Facebook bỏ `margin-left` và collapse cả dấu cách ASCII/tab đầu dòng khi import clipboard HTML, compose runtime phải project mỗi cấp `data-indent` của paragraph/heading có nội dung thành sáu NBSP `&#160;` (trừ node trong list); không dựa vào CSS hoặc whitespace collapsible. Block nhập nội dung phải bám C# DOM: dùng đúng `fb_composer_dialog`, `page.focus` → chờ `facebookStepMs` → `page.paste(..., { mimeType: 'text/html' })` → `page.insertText(' ')`; chỉ retry đúng HTML paste một lần, không thêm selector/toạ độ và không fallback chèn raw HTML.

Zalo rich content được map sang `{ msg, styles }` theo offset UTF-16: bold/italic/underline/strike, heading = Big+Bold, list, blockquote/Indent và paragraph/heading `data-indent` = `Indent(indentSize)`; các cấp indent chồng nhau được cộng thành range không chồng lấn. Canh lề bị bỏ và link khác nhãn thành `nhãn (URL)`. Normal mode có từ 2 attachment trở lên luôn gửi media với `msg=''` trước rồi mới gửi nội dung; một attachment plain giữ caption hiện tại, một attachment formatted gửi nội dung trước rồi media, còn share giữ media trước rồi forward. Khi bước đầu đã thành công nhưng bước sau lỗi, phải ghi partial failure, hoàn tất input và không retry target để tránh gửi trùng; quota vẫn chỉ tính một action/target.

Convention quan trọng (xem memory `campaign_conventions.md`):
- **C# Facebook DOM workflow reference**: khi user cung cấp code C# Facebook automation đã chạy đúng, xem code C# là source-of-truth cho mọi tương tác DOM trong workflow. Trigger nhanh rule này khi user nói các cụm như `C# DOM mode`, `trust C#`, `bám C#`, `làm giống C#`, hoặc `đối chiếu DOM theo C#`. Bắt buộc bám sát C# nếu user không yêu cầu khác: XPath selector giữ nguyên; parent/root dùng để find element giữ nguyên; thứ tự thao tác DOM giữ nguyên; click/scroll/sleep/poll phải mô phỏng đúng hành vi C# nhất có thể trong Electron workflow; không tự thêm fallback selector, selector tiếng Anh, contains-class thay exact-class, visible filter, scroll container fallback, hoặc DOM heuristic khác. Được phép khác C# ở logic ngoài DOM nếu phù hợp hệ thống: lưu DB/upsert/dedupe, logging/progress/cancel, workflow variables, stop policy như `maxNoChangeCycles` nếu user chấp nhận. Trước khi implement workflow từ C#, agent phải trình bày bảng đối chiếu `C# step | Workflow step dự kiến | Khác C# không | Lý do`; nếu cần khác C# ở phần DOM, phải hỏi user trước.
- **Atomic blocks**: tuyệt đối KHÔNG tạo "do-many-things" block. Compose existing primitives (`page.click`/`page.type`/`page.waitForSelector`/...).
- **KHÔNG dùng tọa độ viewport** — webview có thể không focus, `getBoundingClientRect()` clientX/clientY có thể sai. Dispatch synthetic event với `{bubbles, cancelable, view: window}` (no coords).
- **FB timestamp link** lazy-load qua `FocusEvent('focusin')`, không phải hover.
- **Fanpage UI post link**: `fb_post_current_identity_ui` lấy link sau khi composer đóng bằng `FbComposerRawPostLink` → render wait → `FocusEvent('focusin')` → `FbComposerPostLink`; nếu `postUrl=''` nhưng `posted=true` thì vẫn log đăng thành công, chỉ thiếu link.
